# `src/renderer/src/hooks/useDrawingStops.ts` — остановка на кадрах с рисунками

**Назначение:** когда воспроизведение доходит до кадра с рисунком, видео встаёт на этом кадре. Дальше два варианта:
- `'key'` — ждёт любую клавишу или клик;
- `'timer'` — ждёт N секунд с обратным отсчётом, `Space` продолжает сразу.

Работает и при обычном просмотре, и в «Проиграть все»: где именно, решает настройка `holdScope` (её передаёт [App](../App.tsx.md) через `enabled`).

## API

```ts
const stops = useDrawingStops(video, times, fps, { mode, seconds, enabled })
stops.hold          // { time, mode, until, total } | null
stops.release(play) // снять остановку; play=true — продолжить
stops.freeze()      // остановить таймер (начали рисовать / открыли меню) — дальше ждём клавишу
stops.arm()         // перед программной перемоткой: рисунок на кадре, куда перематываем, тоже сработает
```

`times` — локальные времена рисунков **активного видео** (см. `drawingTimes` в [drawingStops.ts](../lib/drawingStops.ts.md)). Хук не знает о моментах и видео, поэтому при переключении видео [App](../App.tsx.md) передаёт новый список.

## Как работает

- Свой цикл `requestVideoFrameCallback`. На каждом показанном кадре, пока видео играет, вызывается `findCrossedDrawing(times, prev, cur)`. `prev` — номер предыдущего кадра непрерывного воспроизведения.
- **Что считается «уже пройденным» (`prev`):**
  - **ручная перемотка** (шаг, таймлайн, клик по моменту) → `prev = null`, а на `play` — текущий кадр. Кадр, на котором пользователь стоит, он уже видит, поэтому повторной остановки на нём нет;
  - **программная перемотка после `arm()`** (старт плейлиста, переход к следующему моменту, переключение видео — через `beforeSeek`) → `prev = кадр − 1`. Рисунок прямо на первом кадре момента тоже вызывает остановку;
  - **собственная перемотка остановки на кадр рисунка** → `prev = кадр рисунка`, чтобы после продолжения он не сработал снова.
  - Перемотка «через» рисунок остановку не вызывает.
- **Найден рисунок** → `pause()`, seek точно на кадр рисунка (флаг `ownSeek`, чтобы собственный seek не снял остановку), состояние `hold`, таймер (в режиме `timer`).
- **Пользователь сам перемотал во время остановки** → остановка снимается без продолжения.
- Параметры (`times`, `fps`, `options`) читаются из ref, поэтому правки рисунков и настроек учитываются сразу.

## Порядок с плейлистом

Цикл этого хука регистрируется раньше, чем цикл [usePlaylist](usePlaylist.ts.md). Если рисунок стоит на последнем кадре момента, сначала срабатывает остановка (видео на паузе), а плейлист пропускает этот кадр и перейдёт к следующему моменту после продолжения.

## Интерфейс

[HoldOverlay](../components/HoldOverlay.tsx.md) — плашка сверху. [App](../App.tsx.md):
- в режиме `key` любая клавиша (кроме одиночных модификаторов и клавиш самого плеера) вызывает `release(true)`;
- `Space` и клик по видео тоже продолжают;
- начало штриха, открытие меню рисования, схемы и настроек вызывают `freeze()`.
