# `src/renderer/src/hooks/usePlaylist.ts` — «проиграть моменты подряд»

## API

```ts
const playlist = usePlaylist(video, fps, moments, {
  videoId, offset,           // активное видео и его сдвиг
  beforeSeek, locate, switchTo
})
playlist.start(items)  // начать с items[0]
playlist.stop()        // выйти из режима
playlist.view          // { ids, index } | null — для интерфейса
```

| Опция | Описание |
|---|---|
| `videoId`, `offset` | Активное видео и его сдвиг |
| `locate(m)` | Где играть момент: `{ videoId, offset }` или `null` |
| `switchTo(videoId, local)` | Переключить видео; когда оно загрузится, перемотать на `local` и запустить |
| `beforeSeek()` | Вызывается перед каждой своей перемоткой (взвод остановок на рисунках) |

## Как работает

- Хранит **только id моментов** и текущий индекс. На каждом кадре id превращаются в актуальные моменты, поэтому правки границ во время паузы сразу учитываются. Удаление текущего момента останавливает проигрывание.
- **Несколько видео.** Момент из другого видео: [App](../App.tsx.md) переключает видео через `switchTo`, плейлист при этом продолжается. Перемотка внутри активного видео — обычная. Плейлист переживает смену `<video>`.
- Цикл `requestVideoFrameCallback` пропускает кадры во время seek и на паузе. Иначе после перехода к следующему моменту пришёл бы ещё старый кадр и вызвал бы двойной переход.
- Время для решения — `mediaTime + offset`, то есть время проекта.
- Решение принимает [decidePlaylistStep](../lib/playlist.ts.md).
- Режим сбрасывается на `ended`, при смене `<video>` и размонтировании.
- Любая ручная перемотка в [App](../App.tsx.md) вызывает `stop()`.

Остановки на кадрах с рисунками вынесены в [useDrawingStops](useDrawingStops.ts.md): они работают и вне плейлиста.
