# `src/renderer/src/lib/time.ts` — время, кадры, скорость

**Назначение:** арифметика времени и кадров для плеера. Чистые функции.

## Экспорт

| Имя | Описание |
|---|---|
| `SPEED_PRESETS` | `[0.25, 0.5, 0.75, 1]` — клавиши `1`–`4` |
| `MIN_RATE`, `MAX_RATE` | 0.1 и 1 (диапазон из брифа) |
| `clamp(v, min, max)` | |
| `frameIndex(t, fps)` | Номер кадра: `floor(t·fps + 1e-6)`. Эпсилон нужен, потому что после seek `currentTime` бывает чуть меньше границы кадра |
| `stepFrameTime(t, fps, delta, duration)` | Время для шага на `delta` кадров, в пределах `[0, последний кадр]` |
| `stepMsTime(t, ms, duration)` | `t + ms/1000` в пределах `[0, duration]` |
| `clampRate(r)` | Ограничение до 0.1–1 с округлением до сотых |
| `formatTime(s, withMs?)` | `83.456` → `1:23.456`, с часами — `1:01:23.456` |
| `parseTime(str)` | `"83.5"`, `"1:23"`, `"1:01:23,5"` → секунды, иначе `null`. Используется при ручном вводе границ момента |

## Почему шаг ставит середину кадра

В брифе было `currentTime += 1/fps`. На практике это накапливает ошибку округления, особенно на 29.97 fps, и seek может попасть в предыдущий кадр. Поэтому `stepFrameTime` считает номер целевого кадра и ставит время **в его середину**: `(n + 0.5) / fps`. Seek в середину кадра всегда показывает именно этот кадр. Проверено e2e-тестом на видео с номерами кадров на картинке.

Ограничение: функция рассчитана на постоянную частоту кадров. Для VFR-видео приложение предлагает конвертацию (см. [probe.ts](../../../main/probe.ts.md)).
