# `src/main/media.ts` — протокол `media://` и отдача файлов

**Назначение:** даёт `<video>` в рендерере читать локальные файлы с поддержкой HTTP Range. Без Range Chromium не умеет перематывать видео.

Почему не `file://`: в dev-режиме страница грузится с `http://localhost`, и оттуда `file://` заблокирован. Свой протокол работает одинаково в dev и в собранном приложении и позволяет ограничить доступ белым списком.

## Экспорт

| Имя | Описание |
|---|---|
| `MEDIA_SCHEME` | `'media'` |
| `toMediaUrl(path)` | `/a/b.mp4` → `media://local/%2Fa%2Fb.mp4`. Весь путь кодируется одним сегментом, поэтому `\`, `:` и пробелы в Windows-путях не ломают URL |
| `fromMediaUrl(url)` | Обратное преобразование |
| `parseRange(header, size)` | Разбирает `bytes=a-b`, `bytes=a-`, `bytes=-n`. Возвращает `{start, end}` или `null`, если диапазон некорректен или выходит за файл |
| `serveFile(path, range)` | `Response` 200 (весь файл), 206 (диапазон) или 416 (неверный диапазон). Файл читается потоком (`createReadStream` → `Readable.toWeb`) и не загружается в память целиком |

## Детали

- `MIME`: по расширению. `.mov` намеренно отдаётся как `video/mp4`: так Chromium надёжнее его воспроизводит.
- Белый список проверяется не здесь, а в обработчике протокола в [index.ts](index.ts.md).
