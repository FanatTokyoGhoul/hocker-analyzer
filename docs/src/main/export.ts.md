# `src/main/export.ts` — рендер клипов через ffmpeg

**Назначение:** превращает запрос экспорта в готовые mp4. Рендерер присылает PNG рисунков, подписей и схем, а main запускает ffmpeg. Чистая сборка команд вынесена в [exportPlan.ts](exportPlan.ts.md).

## Проверка запроса: `validateExportRequest`

Запрос приходит из рендерера, поэтому проверяется всё, что попадёт в ffmpeg и на диск:

| Что | Ограничение |
|---|---|
| Режим | `single` или `separate` |
| Размер кадра | 16–8192 px |
| fps | 1–240 |
| `holdSeconds` | 0–60 |
| Клипов | до 500 |
| Рисунков всего | до 2000 |
| Длительность всего | до 6 часов (клипы, стоп-кадры и схемы вместе) |
| PNG | строка `data:image/png;base64,…`, до 25 МБ каждый; суммарно до 500 МБ |
| Клип | `start ≥ 0`, `end > start` |

## Ход работы: `runExport`

1. Создаётся временная папка `hockey-export-*` в системной `tmpdir`.
2. Для каждого клипа:
   - PNG рисунков, подписи и схемы пишутся во временные файлы;
   - `probe` определяет, есть ли аудио (результат кэшируется по пути видео);
   - `buildClipJob` возвращает аргументы и текст фильтра, фильтр пишется в файл;
   - `runFfmpeg` запускает ffmpeg (`FFMPEG` из [ffmpeg.ts](ffmpeg.ts.md)) и разбирает `-progress pipe:1`.
3. `separate` — каждый клип уже готов в папке назначения (`uniquePath` дописывает `(2)`, `(3)` при совпадении имён).
4. `single` — клипы склеиваются concat-демультиплексором с `-c copy` (без перекодирования), итог переносится в выбранный файл (`rename`, при другом диске — `copyFile`).
5. Временная папка удаляется в `finally`.

Прогресс считается по суммарной длительности: клип плюс стоп-кадры плюс схема (`expectedClipDuration`).

## Отмена и ошибки

- Одновременно идёт только один экспорт (`Экспорт уже идёт`).
- `cancelExport()` ставит флаг и посылает `SIGKILL` текущему ffmpeg.
- При ошибке или отмене удаляются все файлы, которые уже созданы в этом запуске.
- Текст отмены — «Экспорт отменён».
