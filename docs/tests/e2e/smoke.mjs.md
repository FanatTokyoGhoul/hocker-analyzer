# `tests/e2e/smoke.mjs` — сквозной тест приложения

Запускает **настоящее Electron-приложение** через Playwright (`_electron.launch`) и проходит пользовательские сценарии.

```bash
npm run test:e2e -- <video-h264.mp4> [video-hevc.mp4]
```

Видео копируются во временную папку (`E2E_TMP`, по умолчанию системная), чтобы конвертация и сохранение не мусорили рядом с исходниками. `E2E_SHOTS=<папка>` — сохранять скриншоты по ходу теста. `E2E_EXECUTABLE` — запускать указанный бинарник вместо `out/`; для сборки с фьюзами это не работает (см. [electron-builder](../../config/electron-builder.yml.md)).

**Системные диалоги подменяются** в main-процессе (`app.evaluate` → `dialog.showOpenDialog`, `showSaveDialog`, `showMessageBox`), поэтому тест идёт без участия человека. Для выбора файла подменяется только `showOpenDialog`, для сохранения — `showSaveDialog`.

Приложение запускается с `--user-data-dir=<временная папка>/profile`. Поэтому тест не трогает настройки пользователя и всегда начинает с умолчаний (остановка на рисунках на 3 с при любом просмотре, шесть кнопок разметки).

## Сценарии

### Базовые (v0.2)

1. Открыть видео — длительность и fps (30).
2. `Space` — воспроизведение и пауза.
3. `→` ×3, `←` — кадр 2 (по времени и по надписи в интерфейсе).
4. `Shift+→` — ровно +100 мс.
5. `2` → ×0.5, `4` → ×1.
6. Два момента через `I` / `O` / название / теги / `Enter`.
7. Стрелка и круг внутри момента, `Ctrl+Z` убирает круг.
8. Меню рисования на кнопке ✎: HEX `#12AB34` → линия этим цветом → цвет появился в «Недавних».
9. Клик по второй карточке → переход на 8 с; клик по первому блоку на таймлайне → переход на 2 с.
10. «Проиграть все»: оба момента, вне моментов не играет, есть остановка на рисунке, стоп на конце последнего.
11. Настройки: «До нажатия клавиши» → файл записан (`holdMode: "key"`, `version: 1`) → обычное воспроизведение встаёт на кадре с рисунком, стоит 3.5 с, продолжается по клавише.
12. Рисунок прямо на первом кадре второго момента → «▶» этого момента встаёт на нём. `2` во время остановки меняет скорость и не продолжает просмотр, `X` продолжает.
14. `Ctrl+S` — JSON по модели брифа; у фигур сохранены виды и цвета.
15. Перезагрузка и «Открыть проект» — моменты и рисунки на месте.
16. (если передан HEVC) баннер → конвертация → новый файл открыт.

### v0.3 (сценарии 10–20)

Перед сценарием 10 приложение переводится на перемотку к 12 с, чтобы быстрые кнопки работали в середине видео.

| № | Что проверяется |
|---|---|
| 10 | `Shift+1` создаёт момент «Гол 1» на отрезке `[t−8; t+3]` с тегом «гол». `Ctrl+Z` и `Ctrl+Shift+Z` отменяют и возвращают |
| 11 | Заметка к моменту сохраняется и видна в карточке |
| 12 | Новые инструменты: зона кликами, текст, подсветка игрока, пунктирный пас |
| 13 | Колесо мыши увеличивает кадр, `0` сбрасывает |
| 14 | Схема площадки: стрелка нарисована и сохранена в моменте |
| 15 | Статистика по тегам, выгрузка моментов в CSV (UTF-8 BOM) |
| 16 | Второе видео — «следующий период». Момент во времени проекта, клик и «▶ момент» переключают видео |
| 17 | Экспорт подборки с рисунками: длительность файла совпадает с расчётом, стоп-кадры рисунков и схема на месте |
| 18 | Проект v2 на диске: два видео со сдвигами, заметки, схема, новые фигуры |
| 9 | HEVC → предложение конвертации → H.264 с `-g 10` (только если передан второй файл) |
| 19 | Черновик `recovery.json` появляется через несколько секунд после правки. Процесс убивается `SIGKILL`, при запуске предлагается восстановление, и все моменты возвращаются |
| 20 | `F` — полноэкранный просмотр у `.viewer` и выход. Сценарий стоит последним: на некоторых мониторах после полного экрана окно перестаёт отрисовываться |

Нумерация шагов в файле идёт в порядке выполнения: сценарий 9 (HEVC) выполняется после 18, а 19 и 20 — в конце.

Завершение: `app.close()` ждёт до 10 с. Если окно не закрылось (например, после полного экрана), процесс убивается `SIGKILL`. Так тест не зависает.

## Тестовые видео

Удобно генерировать с номером кадра на картинке, тогда точность шага видна на скриншоте:

```bash
ffmpeg -f lavfi -i testsrc2=size=1280x720:rate=30 -f lavfi -i sine -t 20 \
  -vf "drawtext=text='%{n}':fontsize=120:x=40:y=40:fontcolor=white:box=1" \
  -c:v libx264 -g 300 -pix_fmt yuv420p -c:a aac -shortest frames_h264.mp4
ffmpeg -i frames_h264.mp4 -t 6 -c:v libx265 -tag:v hvc1 -c:a copy frames_hevc.mp4
```

`-g 300` (редкие ключевые кадры) сделан намеренно: так проверяется, что шаг точен даже на неудобном файле.
